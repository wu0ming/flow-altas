# Flow Atlas · 个人信息流图谱

Flow Atlas 把分散在工作和生活里的信息流画在一张可维护的图上。你可以从一个工具出发，看到信息从哪来、传给谁、通过什么通道，以及这条路径已经在用、正在测试，还是仍待核实。

## 设计理念

- **先看信息怎么走。** 节点是工具或信息处理单元。连线记录方向、传递的内容、接入通道和状态。比如助手把研究结论交给项目看板，方向、结论和所用 API 各有自己的字段。
- **先看整体，再放大细节。** 首页展示完整关系。进入处理域可看详细流程，放大时出现节点卡片和通道标签。分层视图中，同一工具在各域的显示点对应同一条记录。
- **让维护发生在图上。** 节点、连线和流程可以直接编辑。新节点可以和多条连接一起保存。拖开编辑卡片会解除背景模糊，方便对照图谱修改。
- **让人工和 AI 都能维护。** 页面编辑和 MCP 工具使用同一份数据。人工确认关系和通道，AI 可以根据描述读回已有记录、补齐节点和连线。

## 用途

| 场景 | 可以查什么 |
| --- | --- |
| 盘点工作和生活信息流 | 剪藏、资料整理、协作、交付和归档如何衔接 |
| 管理 AI 助手和工具 | 助手用了哪些 API、MCP 服务、插件或手动操作，哪些信息会进入共享记忆 |
| 调整工作流 | 哪些工具跨域复用，哪些交接重复，哪些关系还需核实 |
| 迭代和备份 | 拖动、缩放、旋转、重算布局，多选对照节点，撤销最近一次修改，导出 JSON |

## 本地运行

使用 Node.js 22 或更新版本。项目无需安装 npm 依赖。

```bash
npm run dev
```

打开 [http://localhost:5173](http://localhost:5173)。本地预览使用内存存储，重启进程会重置预览数据。仓库附带虚构示例。

```bash
npm run build
npm test
```

构建生成 `dist/server/index.js`。生产环境需要为 Worker 提供 R2 绑定 `BUCKET`，并由可信入口完成身份核验、清理外部传入的身份头，再注入 `oai-authenticated-user-id`。在 ChatGPT Sites 中部署时，使用你自己的项目标识与访问控制。更多见 [实现与部署说明](docs/architecture.md)。
